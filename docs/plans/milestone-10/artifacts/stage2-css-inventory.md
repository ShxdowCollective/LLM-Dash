## Primary Findings

- `web/style.css` is roughly 4,515 lines and should be rebuilt as a sectioned
  app layer instead of patched selector-by-selector.
- Delete or replace local Voidware duplication first:
  - the top-level `:root` block currently redefines many package tokens;
  - the later "Voidware component classes" block reimplements `.vw-btn`,
    `.vw-input`, `.vw-modal*`, `.vw-wizard-*`, `.vw-status-chip`, and related
    classes already owned by the 1.0.1 package;
  - duplicate `vw-spin` keyframes exist.
- Preserve app-owned hooks emitted by `web/app.js`:
  - shell/drawer: `.app-sidebar`, `.open`, `data-vw-open`, `.vw-sidebar-link`;
  - settings: `.settings-view`, `.vw-settings-group`, current
    `.vw-settings-group-head` hook;
  - wizard: `#wizard-page`, `.wizard-fullscreen`, `.vw-wizard-step.active`,
    `.wizard-advanced`, `.wizard-footer`;
  - approval: `.voidware-approval-modal.is-submitting`,
    `.voidware-approval-countdown.is-urgent`, `.is-expired`;
  - dense data: `tr.selected`, `.filter-chip.is-active`, `.chart-row`,
    `.changelog-item.is-active`, `.tier-*`, `.progress-indicator[data-state]`.
- Drawer styles overlap package `responsive.css`; choose one app-level contract
  around `.open` / `data-vw-open`.
- Settings markup uses `.vw-settings-group-head`, while Voidware 1.0.1 package
  uses `.vw-settings-group-header`; align only if scoped JS changes stay safe.
- Wizard progress is double-defined; prefer package wizard styles unless
  app-specific composition is necessary.
